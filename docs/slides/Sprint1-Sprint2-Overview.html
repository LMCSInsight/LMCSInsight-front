Auth system & front-end pages overview

Sprint 1

Authentication system

  • Login page – Email + password, error handling, optional “Google” (UI only)
  • Auth API – authApi.login() → JWT + user; role-based redirect
  • AuthContext – currentUser, login(), logout(), persistence in localStorage
  • Protected routes – Unauthenticated users redirected to /auth/login
  • Role-based redirect – After login: RESEARCHER → /dashboard/researcher/:id; DIRECTOR, ASSISTANT, ADMIN → their dashboards
  • Forgot password – Route /auth/forgot-password (placeholder page)

Auth flow (high level)

User opens app → redirect to Login if not authenticated.

User submits email/password → backend returns token + user → login(user, token) → store in context + localStorage → redirect to getDashboardPath(role, user).

Researcher: /dashboard/researcher/{id} (own portal). Any visit to /dashboard without auth → Login.

Sprint 2 – UI

Front-end structure

  • Router – Auth routes (login, forgot-password), dashboard under ProtectedRoute
  • Researcher portal – /dashboard/researcher/:researcherId with nested routes (dashboard, supervisions, students, statistics, profile)
  • ResearcherPortalGuard – Ensures current user is the researcher for :researcherId; otherwise redirect to own portal or role dashboard
  • Other roles – Director, Assistant, Admin dashboards (placeholders) under RoleRoute

Layouts

  • AuthLayout – Wraps login & forgot-password (centered card style)
  • DashboardLayout – Wraps all dashboard routes (Ant Design Layout + sidebar for non-researcher)
  • ResearcherPortalLayout – Fixed sidebar (logo, user card, nav: Dashboard, Supervisions, Students, Statistics, Profile; theme + language + notifications in header; logout). Main content scrolls; sidebar stays fixed.

Researcher pages (implemented)

  • Researcher Dashboard – Stat cards (Total, In Progress, Defended, Pending Validation), Recharts (Pie: by type; Bar: by year), Recent Supervisions table (dots menu: Update / Delete), action buttons (Add New Supervision, Register Student, View All Supervisions)
  • My Supervisions – “My Supervisions (N total)”, toolbar (search, Filters, Add New), active filters bar (chips + Clear All), table (Title, Student, Type, Status, Validation, Actions with dots → Update/Delete), pagination (items per page, Prev/Next, page numbers)
  • Filters panel – Slide-over: Type, Status, Validation status (checkboxes), Academic year, Theme (dropdowns), Start date range; Apply Filters / Reset

Researcher pages (placeholders)

  • Create Supervision (/supervisions/new)
  • Supervision Detail (/supervisions/:id)
  • Edit Supervision (/supervisions/:id/edit)
  • Student Management (/students)
  • Statistics & Reports (/statistics)
  • Profile & Settings (/profile)

All wired in router and sidebar nav; content is placeholder text.

Tech & UX (Sprint 2)

  • UI: React, shadcn (Base UI), Tailwind, Recharts, Lucide icons
  • i18n: react-i18next for sidebar and header labels
  • Theme: ThemeContext (light/dark) in header
  • Buttons: icon + text on one line (whitespace-nowrap, inline-flex)
  • Supervisions list: mock data; search and filters (type, status, validation, year, theme, date range) applied client-side; pagination

Summary

Sprint 1: Auth (login, JWT, context, protected + role-based routes).

Sprint 2: Researcher portal with fixed sidebar, dashboard with charts & table, full supervisions list with search, filters, and pagination.
